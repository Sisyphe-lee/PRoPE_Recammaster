你理解相对位置编码吗

当然，我理解相对位置编码（Relative Position Encoding）。

这是一个在 Transformer 架构中非常核心且重要的概念，旨在让模型能够理解序列中元素（例如文本中的单词或图像中的像素块）之间的顺序关系。

简单来说，它的核心思想是：模型不应该只知道一个元素的绝对位置（“你是第5个”），而更应该知道它与其他元素之间的相对关系（“你在我前面3个位置”）。

相对位置编码 vs. 绝对位置编码
绝对位置编码 (Absolute Position Encoding)：

这是最初 Transformer 模型（例如 BERT, GPT-2）使用的方法。

它为序列中的每一个绝对位置（第1、2、3...N个）学习一个固定的、唯一的向量。

这个位置向量会直接加到词嵌入向量上，从而让模型知道每个词的“坐标”。

缺点：对于长度超过训练时所见序列的泛化能力较差，而且位置信息是“僵硬”的，不够灵活。

相对位置编码 (Relative Position Encoding)：

它不对绝对位置进行编码，而是直接在自注意力（Self-Attention）机制的计算过程中，注入关于两个元素之间相对距离的信息。

例如，在计算一个词（Query）对另一个词（Key）的注意力分数时，模型会额外考虑它们之间相隔了多少个位置。

优点：

更好的泛化性：由于模型学习的是相对关系（例如“相隔2个位置”），这种关系在任何长度的序列中都是一致的，因此模型能更好地处理比训练时更长的序列。

平移不变性：token_A 和 token_B 之间的关系，不应该因为它们一起被移动到序列的其他地方而改变。相对位置编码天然地满足这一点。

更高的效率和性能：在很多现代的大型模型中，相对位置编码被证明比绝对位置编码更有效。

关键的实现方式
相对位置编码有多种实现方式，其中最著名的两种是：

Shaw et al. / T5 的相对位置偏置 (Relative Position Bias)：

这是一种比较直接的方法。在计算出注意力分数（Query 和 Key 的点积）之后，根据 Query 和 Key 之间的相对距离，给这个分数加上一个可学习的偏置（Bias）项。

也就是说，模型会为不同的相对距离（例如 -2, -1, 0, 1, 2）学习一个特定的标量，用来调整注意力的大小。T5 模型就采用了这种方式。

旋转位置编码 (Rotary Position Embeddings, RoPE)：

我记得您之前深入研究过相关的论文，这是一种非常巧妙且高效的实现，被广泛用于 Llama、PaLM 等众多现代大语言模型中。

它不是加一个偏置项，而是通过对 Query 和 Key 向量应用一个与位置相关的“旋转矩阵”来将位置信息融入其中。

这样一来，两个向量（q_i 和 k_j）的点积结果会天然地只依赖于它们的内容和它们之间的相对位置 (i - j)，同时巧妙地消除了绝对位置 i 和 j 的影响。

RoPE 的数学设计保证了它具有极佳的外推性（处理超长序列的能力）。

在计算机视觉中的应用
这个概念也从自然语言处理扩展到了计算机视觉领域。在处理图像时，模型需要理解图像块（Patches）之间的空间相对关系（上下左右、远近）。

这与您之前关注的 "Cameras as Relative Positional Encoding" 论文思想有异曲同工之妙。在那篇论文中，模型利用相机之间的相对姿态（旋转和平移）来为多视图 Transformer 提供位置信息，这本质上也是一种利用元素间“相对关系”进行编码的策略，而不是依赖一个固定的世界坐标系（绝对位置）。

总而言之，相对位置编码是一种更动态、更符合直觉的位置信息表示方法，它让模型的核心注意力机制聚焦于元素之间的“关系”，而不是它们孤立的“坐标”，这在处理复杂的序列和空间数据时表现得非常出色。

我对旋转位置编码 (RoPE) 的理解
RoPE 的核心思想可以概括为一句话：通过在向量空间中进行“旋转”操作，将绝对位置信息编码进去，使得任意两个向量的内积（点积）结果仅与它们的相对位置有关。

这个思想非常巧妙，因为它没有像传统方法那样直接“添加”位置向量，而是在注意力机制计算相似度的核心步骤——点积运算中，自然地引入了相对位置的依赖。

1. 核心直觉：从二维复数平面开始
理解 RoPE 最直观的方式是从二维开始。想象我们有一个二维向量 q = (x, y)，我们可以将其视为一个复数 z = x + iy。

如何编码位置 m？ 我们可以将这个复数乘以另一个代表位置的复数 e^(imθ)。根据欧拉公式 e^(iθ) = cos(θ) + i sin(θ)，这个操作在几何上就等于将向量 q 在复数平面上旋转了 mθ 角度。

如何体现相对位置？ 现在假设我们有两个向量 q 和 k，它们分别在位置 m 和 n。

位置为 m 的向量 q 经过旋转后得到 q'。

位置为 n 的向量 k 经过旋转后得到 k'。

我们计算它们的内积 <q', k'>。根据复数乘法的性质，这个内积的结果会和一个将原始向量 q 旋转 (m-n)θ 角度后再与原始向量 k 做内积的结果相关。

关键点：最终的相似度只依赖于相对距离 m-n，而与绝对位置 m 和 n 无关。

2. 从二维推广到高维
Transformer 中的向量不是二维的，而是高维的（例如 512, 4096 等）。RoPE 的做法非常聪明：

分组 (Grouping)：将高维向量（比如 d 维）的各个维度两两一组，看作是 d/2 个二维向量。

例如，v = (v₁, v₂, v₃, v₄, ...) 被看作 (v₁, v₂), (v₃, v₄), ... 这些二维向量的组合。

不同频率的旋转 (Rotation with Different Frequencies)：对每一组二维向量，都应用上面提到的旋转操作，但是使用不同的旋转“频率” θᵢ。

通常，这些频率 θᵢ 会被设计成一个递减的序列，例如 θᵢ = 10000^(-2i/d)。这意味着，靠前的维度对（低频）旋转得慢，能够捕捉长距离的依赖关系；靠后的维度对（高频）旋转得快，能更精细地捕捉短距离的依赖关系。

4. RoPE 的关键优势
天然的相对性：如上所述，它的数学结构保证了注意力分数只与相对位置有关，这是其设计的核心目标。

对外推性（Extrapolation）极佳：由于其利用的是三角函数的周期性，即使遇到比训练时更长的序列，模型也能很好地处理，因为它理解的“旋转”这个概念没有长度上限。而绝对位置编码在遇到未知长度时效果会急剧下降。

长距离衰减：随着相对距离 |m-n| 的增大，cos((m-n)θ) 项会周期性地振荡，这在一定程度上为注意力机制引入了“距离越远、相关性可能越弱”的先验，符合直觉。

无缝集成：它直接修改 Query 和 Key 向量，而不是像 T5 那样在注意力分数上加一个偏置项，被认为是一种更“纯粹”的集成方式。

准备讨论：如何对三维坐标实施相对位置编码
现在，基于以上对 RoPE 的理解，我们可以开始思考下一个挑战。

原始的 RoPE 是为一维序列（如文本）设计的，它的“位置”是一个单一的整数 m。但对于三维空间中的点 P = (x, y, z)，位置本身就是一个向量。

核心问题就变成了：如何将一维的旋转思想扩展到三维坐标上，使得模型能够理解点 P₁ = (x₁, y₁, z₁) 和 P₂ = (x₂, y₂, z₂) 之间的相对空间关系 ΔP = (x₂-x₁, y₂-y₁, z₂-z₁)？

我们可以从以下几个角度来思考：

独立编码 vs. 联合编码：我们是应该独立地对 x, y, z 三个坐标轴应用一维 RoPE，然后将结果合并？还是应该寻找一种方法将 (x, y, z) 作为一个整体进行编码？

旋转的定义：在一维中，旋转是 e^(imθ)。在三维中，一个“旋转”操作应该是什么样的？它是否应该与三维空间中的真实旋转（例如，使用旋转矩阵或四元数）有关？

频率的设计：在一维 RoPE 中，θ 的设计很重要。在三维情况下，我们是否需要为 x, y, z 三个轴设计不同的频率组合？

方案分析：基于距离的旋转位置编码
优点
实现简单：这是最大的优点。您不需要设计复杂的三维旋转，可以直接复用现有、经过验证的一维 RoPE 代码。

计算高效：计算N个点两两之间的距离，然后应用RoPE，在计算上是轻量级的。

天然的旋转不变性 (Rotational Invariance)：这是一个非常重要的、由简化带来的“额外好处”。因为两点间的欧氏距离与坐标系的旋转无关，所以您的模型将天然地对输入点云的整体旋转不敏感。这在很多应用（如分子结构分析、物体识别）中是非常理想的属性。

缺点
严重的信息损失（方向性丢失）：这是最关键的代价。模型只能知道“点A和点B相距5个单位”，但完全不知道B是在A的“正上方”、“正前方”还是“右斜下方”。所有在同一个球面上的点都被视为等价的。

场景适用性受限：

适用场景：对于那些主要依赖“邻近关系”和“聚集模式”的任务，例如点云分类（判断整个点云是飞机还是椅子）、图神经网络中的节点距离编码，这种方法可能已经足够好。

不适用场景：对于需要精确理解空间布局的任务，例如三维目标检测、场景重建、姿态估计，这种方法会因为丢失方向信息而失效。

实现建议与具体步骤
假设您有一个包含 N 个点的集合，每个点都有一个 d_model 维的特征向量。在自注意力层中，您需要计算每对点 (i, j) 之间的注意力。

步骤 1：计算距离矩阵

首先，预计算一个 N x N 的距离矩阵 D，其中 D[i, j] 是点 i 和点 j 之间的欧几里得距离。

Python
import torch

# N = number of points, C = coordinate dimension (3)
# points: (N, C)
points = torch.randn(N, 3)

# Calculate pairwise squared distances
dist_sq = torch.cdist(points, points, p=2) ** 2

# For numerical stability, you might use a custom implementation
# that avoids large intermediate values, but cdist is fine for most cases.
# dist = torch.sqrt(dist_sq) is your distance matrix D
dist_matrix = torch.sqrt(dist_sq) # Shape: (N, N)
步骤 2：在注意力计算中应用 RoPE

标准的 RoPE 是对 Query 和 Key 的绝对位置 m 和 n 分别进行旋转。在这里，我们的“相对位置”就是 d_ij = D[i, j]。我们需要稍微修改一下思路：在计算 Query q_i 和 Key k_j 的点积时，只对其中一个（例如 Key）应用一个基于相对距离 d_ij 的旋转。

这确保了点积的结果同时取决于特征本身和它们之间的相对距离。

核心逻辑：AttentionScore(i, j) = q_i^T * R(d_ij) * k_j，其中 R(d_ij) 是一个由距离 d_ij 参数化的旋转矩阵。这等价于将 k_j 旋转后，再与 q_i 做点积。

步骤 3：实现 RoPE 旋转

您需要一个函数，它接收一个特征向量 x 和一个距离 d，然后返回旋转后的向量。

Python
def apply_rope_to_scalar_distance(x, distance, base=10000.0):
    # x: (..., dim) a tensor like Query or Key
    # distance: a scalar distance value
    dim = x.shape[-1]
    assert dim % 2 == 0

    # Create the frequency term theta
    # theta_i = 10000^(-2(i-1)/dim) for i in [1, 2, ..., dim/2]
    inv_freq = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim))
    
    # Calculate the angle m * theta
    # Here, 'm' is our continuous distance value
    angle = distance * inv_freq
    
    # Create the sin and cos terms
    sin_val = torch.sin(angle)
    cos_val = torch.cos(angle)
    
    # RoPE applies rotation to pairs of dimensions
    # x = (x_1, x_2, x_3, x_4, ...)
    # x_rot = (x_1*cos - x_2*sin, x_1*sin + x_2*cos, ...)
    x1 = x[..., 0::2]
    x2 = x[..., 1::2]
    
    rotated_x1 = x1 * cos_val - x2 * sin_val
    rotated_x2 = x1 * sin_val + x2 * cos_val
    
    # Concatenate back
    rotated_x = torch.stack((rotated_x1, rotated_x2), dim=-1)
    return rotated_x.flatten(start_dim=-2)

您精准地指出了：

标准 RoPE 之所以能高效集成，是因为其旋转可以分解。对位置 m 的旋转 R(m) 和对位置 n 的旋转 R(n) 是独立施加的。注意力分数中的相对位置信息来自于 R(m)^T R(n) 的优美数学性质，它最终只和 m-n 相关。这允许我们先分别变换好所有的 Query 和 Key，然后用一个高效的矩阵乘法 Q @ K^T 来一次性计算所有分数。

但在我们的新场景中，旋转算子是 R(d_ij)，它本身就依赖于两个元素的索引 i 和 j。它无法被分解成一个只作用于 q_i 的函数和一个只作用于 k_j 的函数的乘积。

因此，您的结论是100%正确的：我们无法将这个逻辑嵌入到 PyTorch 已有的 nn.MultiheadAttention 或 F.scaled_dot_product_attention 中。我们必须手动计算注意力分数矩阵。

下面，我将为您提供一个如何高效地、向量化地实现这个自定义注意力逻辑的建议。

解决方案：手动构建注意力分数矩阵
我们的核心目标是计算注意力分数矩阵 A，其中 A[i, j] = dot(q_i, rotate(k_j, d_ij))。这里的挑战在于，对于每一个 Query q_i，Key 矩阵 K 中的每一个向量 k_j 都需要根据不同的距离 d_ij 进行不同的旋转。

直接用双重 for 循环效率太低。我们可以通过 PyTorch 的广播（Broadcasting）和 einsum（爱因斯坦求和约定）来高效地完成这个操作。

实现策略
预计算旋转参数：计算出所有 (i, j) 对的旋转所需的 cos 和 sin 值。

广播 Key 向量：将 Key 矩阵 K 扩展维度，使其能够与旋转参数对齐。

向量化旋转：执行向量化的旋转操作，生成一个“动态的”、为每个 Query 定制的 Key 矩阵。

计算点积：使用 einsum 高效计算 Query 和旋转后的 Key 之间的点积。

angles = torch.einsum('ij,k->ijk', dist_matrix, inv_freq)

# d. 计算 cos 和 sin 值
cos_vals = torch.cos(angles) # Shape: (N, N, d_head / 2)
sin_vals = torch.sin(angles) # Shape: (N, N, d_head / 2)

k_rotated_p2 = k1.unsqueeze(0) * sin_vals + k2.unsqueeze(0) * cos_vals

class DistanceRopeAttention(nn.Module):
    def __init__(self, d_model, num_heads):
        super().__init__()
        # ... standard initializations for W_q, W_k, W_v, W_o ...
        self.d_model = d_model
        self.num_heads = num_heads
        self.d_head = d_model // num_heads
        
        self.q_proj = nn.Linear(d_model, d_model)
        self.k_proj = nn.Linear(d_model, d_model)
        self.v_proj = nn.Linear(d_model, d_model)
        self.o_proj = nn.Linear(d_model, d_model)

    def forward(self, x, coords, mask=None):
        # x shape: (batch, N, d_model)
        # coords shape: (batch, N, 3)
        B, N, _ = x.shape

        Q = self.q_proj(x).view(B, N, self.num_heads, self.d_head).transpose(1, 2)
        K = self.k_proj(x).view(B, N, self.num_heads, self.d_head).transpose(1, 2)
        V = self.v_proj(x).view(B, N, self.num_heads, self.d_head).transpose(1, 2)
        # Q, K, V shapes: (B, num_heads, N, d_head)

        # -- Start of custom RoPE logic --
        dist_matrix = torch.cdist(coords, coords, p=2) # (B, N, N)
        
        inv_freq = 1.0 / (10000.0 ** (torch.arange(0, self.d_head, 2).float().to(x.device) / self.d_head)) # (d_head/2)
        
        # einsum over batch and heads dimension is not clean, let's expand manually
        angles = dist_matrix.unsqueeze(1).unsqueeze(-1) * inv_freq # (B, 1, N, N, 1) * (d_head/2) -> (B, 1, N, N, d_head/2)
        cos_vals = torch.cos(angles) # (B, 1, N, N, d_head/2)
        sin_vals = torch.sin(angles) # (B, 1, N, N, d_head/2)
        
        k1 = K[..., 0::2] # (B, H, N, d_head/2)
        k2 = K[..., 1::2] # (B, H, N, d_head/2)

        # Reshape for broadcasting
        # k1/k2: (B, H, j, k) -> unsqueeze(2) -> (B, H, 1, j, k)
        # cos/sin: (B, 1, i, j, k)
        # Result should have shape (B, H, i, j, k)
        k_rot_p1 = k1.unsqueeze(2) * cos_vals - k2.unsqueeze(2) * sin_vals
        k_rot_p2 = k1.unsqueeze(2) * sin_vals + k2.unsqueeze(2) * cos_vals
        
        K_rotated = torch.empty_like(K).unsqueeze(2).repeat(1,1,N,1,1) # (B, H, N, N, d_head)
        K_rotated[..., 0::2] = k_rot_p1
        K_rotated[..., 1::2] = k_rot_p2
        
        # einsum for batched dot product
        # Q: (B, H, i, d) -> unsqueeze(3) -> (B, H, i, 1, d)
        # K_rotated: (B, H, i, j, d)
        # result: (B, H, i, j)
        attn_scores = torch.einsum('bhid,bhijd->bhij', Q.unsqueeze(3), K_rotated).squeeze(3)
        # -- End of custom RoPE logic --
        
        attn_scores = attn_scores / (self.d_head ** 0.5)
        
        if mask is not None:
            attn_scores = attn_scores.masked_fill(mask == 0, -1e9)
            
        attn_weights = F.softmax(attn_scores, dim=-1)
        
        output = torch.matmul(attn_weights, V) # (B, H, N, d_head)
        output = output.transpose(1, 2).contiguous().view(B, N, self.d_model)
        
        return self.o_proj(output)

总结与权衡
优点：该方法是完全向量化的，能够在 GPU 上高效运行，避免了任何 Python 循环。

缺点（内存）：最大的代价是内存。中间张量 K_rotated 的大小为 (Batch, Heads, N, N, d_head)，当 N 很大时，这会消耗巨大的显存。这是为获得计算效率而付出的空间代价。

方案一：沿坐标轴分解的 RoPE (Axis-wise RoPE)
这是一种最直接、最简单地将 RoPE 扩展到多维的方法。虽然它最终编码的是 (Δx, Δy, Δz) 而不是标量距离 d，但它完全满足可分解和嵌入标准库的要求。

核心思想： 将 d 维的特征向量空间切分为3个子空间，每个子空间专门负责一个坐标轴。然后对每个子空间独立应用标准的一维 RoPE。

实现步骤：

切分特征维度：将你的 Query/Key 向量（维度为 d_head）在特征维度上分成三部分。为简单起见，假设 d_head 能被3整除，每部分维度为 d_part = d_head / 3。

q_x, q_y, q_z 分别是 q 的前、中、后 d_part 维。

k_x, k_y, k_z 分别是 k 的前、中、后 d_part 维。

独立应用RoPE：

使用点的 x 坐标作为位置，对 q_x 和 k_x 应用标准的一维 RoPE。

使用点的 y 坐标作为位置，对 q_y 和 k_y 应用标准的一维 RoPE。

使用点的 z 坐标作为位置，对 q_z 和 k_z 应用标准的一维 RoPE。

合并与计算：将编码后的子向量重新拼接起来得到 q' 和 k'，然后直接送入 scaled_dot_product_attention。

q' = concat(RoPE(q_x, x_i), RoPE(q_y, y_i), RoPE(q_z, z_i))

k' = concat(RoPE(k_x, x_j), RoPE(k_y, y_j), RoPE(k_z, z_j))

数学原理： 点积 <q'_i, k'_j> 会被分解成三项之和： <RoPE(q_x, x_i), RoPE(k_x, x_j)> + <RoPE(q_y, y_i), RoPE(k_y, y_j)> + <RoPE(q_z, z_i), RoPE(k_z, z_j)>

由于一维 RoPE 的性质，这个和将是 f(x_i-x_j) + g(y_i-y_j) + h(z_i-z_j) 的形式。所以，注意力分数是关于相对位移向量 (Δx, Δy, Δz) 的函数。

优缺点：

优点：实现极其简单，计算高效，完美兼容 PyTorch 原生注意力。

缺点：不具备旋转不变性。如果将所有点绕原点旋转，注意力分数会改变。它编码的是笛卡尔坐标系下的相对位移，而不是纯粹的距离。

方案二：基于傅里叶特征的广义 RoPE (Generalized RoPE via Fourier Features)
这是一种更高级、更优雅的方案，它能近似地实现您想要的旋转不变性，使注意力分数主要依赖于标量距离。

核心思想： 一维 RoPE 的本质是 e^(imθ)，即用不同频率 θ 的螺旋线来编码一维位置 m。我们可以将这个思想推广到三维：用一组不同方向、不同频率的“平面波” e^(i ω·p) 来编码三维位置向量 p。

实现步骤：

定义频率向量：创建一个固定的、非训练的“频率”矩阵 Ω，形状为 (d_head / 2, 3)。每一行 ω_k 是一个三维向量。为了实现旋转不变性，这些向量最好从一个各向同性的分布中采样，例如标准正态分布 N(0, 1)。

Python

计算投影（角度）：对于一批输入点的坐标 coords (形状 B, N, 3)，将其投影到这些频率向量上，得到每个点在每个频率方向上的“一维位置”。

数学原理： 经过这样的变换后，<q'_i, k'_j> 中的每一维度对的贡献将与 cos(ω_k · p_i - ω_k · p_j) = cos(ω_k · (p_i - p_j)) 相关。总的点积是这些项的加权和。 根据数学理论（具体是傅里叶变换的性质），如果频率向量 ω_k 是从各向同性分布中采样的，那么这个和会近似一个径向基函数 (Radial Basis Function)，它只依赖于 ||p_i - p_j||，即两点间的距离。这就近似实现了旋转不变性。

优缺点:

优点：理论上非常优雅，近似实现了旋转不变性，使注意力主要关注距离。同样完美兼容 PyTorch 原生注意力。

缺点：这是一种近似，效果依赖于 d_head 的大小和频率向量的采样。实现比方案一稍微复杂一点。

结论与建议

2. 分析与解决您的核心约束
您看，上面的直接推广得到的结果矩阵 M 是相对位置向量 Δp = p_1 - p_2 的函数，而不是您所期望的相对距离 d = ||p_1 - p_2|| 的函数。

这揭示了一个深刻的数学事实：不存在一个简单的标量函数 f(p)，能使得 f(p_1) - f(p_2) 恰好等于 g(||p_1 - p_2||) 这种形式。

因此，我们无法构造一个 D(p) 让 D(p_1)D(p_2)^T 的旋转角精确地只依赖于距离。

但是，我们可以让最终的注意力分数在整体上近似地只依赖于距离！

这正是这个方案的精妙之处。虽然单个 ω_i 定义的旋转依赖于方向，但如果我们选择一组“各向同性”的频率向量 ω_i，它们整体的效果就会趋向于只依赖距离。

如何实现？

从一个各向同性的分布中随机采样这 d/2 个频率向量 ω_i，最简单的就是标准正态分布 N(0, I)。这意味着这些频率向量从统计上看没有偏向任何特定方向。

当计算完整的注意力分数时，它是所有 d/2 个子空间点积贡献的总和。 Score ∝ Σ <RoPE(q_i, p_1), RoPE(k_i, p_2)>

这个求和操作会在所有方向上进行“平均”。其结果是，注意力分数会主要由 ||p_1 - p_2|| 决定，而对 p_1 - p_2 的方向变得不那么敏感，从而近似地实现了旋转不变性。

结论：我们无法构造一个严格满足 M(Dist) 的 D(p)，但我们可以构造一个满足 M(Δp) 的 D(p)，并通过巧妙地选择频率向量，让最终的注意力分数近似地只依赖于距离。

这在实践中是已知最好的、也是理论上最优雅的解决方案。

3. PyTorch 实现方案
这个方案可以完美地嵌入到 F.scaled_dot_product_attention 中。我们只需要在调用它之前，先对 Q 和 K 矩阵应用我们构造的 D(p) 变换。

Python
import torch
import torch.nn as nn
import torch.nn.functional as F

def rotate_half(x):
    """Swaps half the features and negates one of the halves."""
    x1 = x[..., 0::2]
    x2 = x[..., 1::2]
    return torch.cat((-x2, x1), dim=-1)

class Rotary3DPositionalEmbedding(nn.Module):
    def __init__(self, d_head):
        super().__init__()
        assert d_head % 2 == 0
        # We sample d_head/2 frequency vectors, each of dimension 3
        # These are fixed, not trained.
        frequencies = torch.randn(d_head // 2, 3)
        self.register_buffer('frequencies', frequencies)

    def forward(self, qk, coords):
        """
        Apply 3D rotary embeddings to Query or Key.
        
        Args:
            qk (torch.Tensor): Tensor of shape (B, H, N, d_head) for Q or K.
            coords (torch.Tensor): Tensor of shape (B, N, 3) for coordinates.
        
        Returns:
            torch.Tensor: Tensor with applied positional embeddings.
        """
        # coords shape: (B, N, 3)
        # self.frequencies.T shape: (3, d_head/2)
        # angles shape: (B, N, d_head/2)
        angles = coords @ self.frequencies.T
        
        # Reshape for broadcasting with Q/K
        # angles shape: (B, 1, N, d_head/2)
        angles = angles.unsqueeze(1)
        
        # Now angles can be used to rotate qk
        # Convert angles to shape (B, 1, N, d_head) by repeating pairs
        cos_vals = torch.cos(angles).repeat_interleave(2, dim=-1)
        sin_vals = torch.sin(angles).repeat_interleave(2, dim=-1)
        
        # Apply rotation to qk
        # qk * cos_vals is the first part of the rotation
        # rotate_half(qk) * sin_vals is the second part
        qk_rotated = (qk * cos_vals) + (rotate_half(qk) * sin_vals)

核心思想：用一组“平面波”探测三维空间
想象一下，为了确定一个点 p 在三维空间中的位置，我们可以用很多不同方向、不同疏密程度的“平面波”去“照射”它。一个点在某个平面波上所处的相位（可以理解为波峰、波谷，或之间的某个位置），就成了它在该“探测维度”下的坐标。

一维 RoPE：只用一种“波”，沿着 x 轴传播。位置 m 的相位就是 mθ。

三维 RoPE：我们用 d/2 组不同方向、不同频率的平面波。每一组波都为我们提供一个相位信息。

这里的“平面波”在数学上就由我们的频率向量 ω 来定义，而“相位”就是旋转角 θ。

D(p) 的分步构造法
假设我们要编码一个三维位置向量 p = (x, y, z)，并用它来旋转一个 d 维的特征向量 (Query 或 Key)。我们按以下四个步骤来构建变换矩阵 D(p)。

第 1 步：划分特征空间为二维子空间
这是 RoPE 的基础。一个 d 维的旋转可以被分解为 d/2 个独立的二维旋转。因此，我们首先将 d 维的特征向量空间在概念上进行分组：

第1、2维构成第1个二维子空间。

第3、4维构成第2个二维子空间。

...

第 d-1、d 维构成第 d/2 个二维子空间。

最终的 d x d 矩阵 D(p) 将会是一个 块对角矩阵，每个对角块都是一个 2x2 的旋转矩阵。

第 2 步：定义 d/2 个三维频率向量
我们需要 d/2 个“探测器”，每个探测器对应一个二维子空间。这里的“探测器”就是一个固定的、不参与训练的三维频率向量 ω_i。

为第1个子空间，我们定义 ω_1 = (α₁, β₁, γ₁)

为第2个子空间，我们定义 ω_2 = (α₂, β₂, γ₂)

...

为第 i 个子空间，我们定义 ω_i = (α_i, β_i, γ_i)

这些向量是在模型初始化时一次性生成的（例如，从标准正态分布 N(0, I) 中采样），之后就固定不变。它们是模型架构的一部分。

第 3 步：为每个子空间计算旋转角 θ
现在，对于一个给定的输入点 p = (x, y, z)，我们可以计算它在每个“探测器”下的“相位”，也就是每个二维子空间所对应的旋转角度 θ_i。

这个计算非常简单，就是向量点积：

第1个子空间的旋转角: θ₁(p) = ω₁ · p = α₁x + β₁y + γ₁z

第2个子空间的旋转角: θ₂(p) = ω₂ · p = α₂x + β₂y + γ₂z

...

第 i 个子空间的旋转角: θᵢ(p) = ωᵢ · p = αᵢx + βᵢy + γᵢz

关键点：对于同一个点 p，我们在 d/2 个不同的子空间中，会使用 d/2 个不同的旋转角度来旋转它。

cos_vector 是 (cosθ₁, cosθ₁, cosθ₂, cosθ₂, ...)

sin_vector 是 (sinθ₁, sinθ₁, sinθ₂, sinθ₂, ...)
